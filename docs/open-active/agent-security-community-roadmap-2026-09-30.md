# Agent 安全社区贡献与 KoawaAgent 学习路线

日期：2026-09-30。周期：8 个学习周，从实际启动周计；不因等待社区回复压缩实验时间。

状态：规划文档，尚未启动外部贡献。本文不表示已获社区接纳、发现上游漏洞或取得真实服务测试授权。

## 1. 目标与边界

主线：学习并贡献 Agent 运行时的安全边界验证，先从安全评测有效性进入，再延伸到执行证据与恢复。KoawaAgent 是实验场，不是对其他项目具有约束力的参考标准。

8 周可控目标：完成一个自己能解释、他人能复现的案例包；若符合目标社区规则且获得用户发送授权，再提交一项有用的复现、测试或小修复，并处理收到的反馈。合并、维护者回复速度、CVE 数量不作为完成条件。

约束：

- 每周最多约 10 小时，5 天，每天约 2 小时；考虑注意力波动，必做内容只安排约 7 小时，剩余作为实验失败、阅读与休息缓冲。
- 同时只维护一个主要社区候选和一个主要问题，不同时开展全仓审计、多篇论文复现和大型框架重构。
- 本次仅制定计划。未授权安装依赖、运行真实模型付费实验、发布仓库、发送 issue/PR/私密报告、自动跟踪社区或联系维护者。
- KoawaAgent 的代码实现、提交和推送仍按单独授权执行；不要覆盖其他实施会话的工作。
- 后续在其他项目操作时，以该项目自己的 AGENTS、贡献与安全政策为准，不把 V2 规则自动套到上游。

## 2. 方向与社区选择

主候选：AgentDojo。理由是本轮已核实其攻击/防御评测定位和贡献入口，且已有执行轨迹与实际副作用判定的公开讨论，与当前学习积累接近。它是候选，不是已决定投入长期开发；第 1 周核对最新维护状态、重复项和环境成本后确认。

旁听渠道：OWASP GenAI Security。用于理解威胁分类、阅读工程案例和交流，不另开一条重型交付任务。无需以加入会员作为贡献前提。

后续工程目标：先把评测贡献做扎实，再考虑实际 Agent runtime 的执行身份、消息送达、恢复或权限边界。不要为了扩大履历频繁切换仓库。

选择主仓库的检查项：

1. 有明确贡献规则、安全报告入口，能找到近期相关讨论与维护者互动。
2. 问题可缩到一个组件，能在隔离本地环境或 mock 下复现。
3. 不依赖真实秘密、生产账户或未批准的模型预算。
4. 没有已经解决或正在由他人实施的同一项工作；已有 issue 优先补充新证据，不重复报题。
5. 用户能说明目标路径，而不是只能转述 Agent 的结论。

若候选不满足条件：先保留独立案例包，不为找漏洞而硬套问题；再评估一个替代项目。不得把维护者暂未回复解释为拒绝或项目失效。

## 3. 首个选题

题目：安全评测是否在目标路径未执行时“空转通过”？

研究问题：工具未执行、检索未命中、初始化失败或请求被拒绝时，评测是否把这些情况无条件计为防御成功？特别区分真正拦截了攻击，与任务根本未成功运行。

本地来源：此前 KoawaAgent 的检索防泄漏测试未绑定 turn，实际只返回 recall_unavailable，却因输出中没有秘密而通过。修正时先断言调用成功、确实命中，再检查允许返回的结果。这是本地已验证案例，不证明 AgentDojo 或其他项目存在相同缺陷。

最小实验矩阵：

| 场景 | 必须观察的证据 | 不能直接推出的结论 |
| --- | --- | --- |
| 无攻击的正常任务 | 目标路径执行、工具结果、任务结果 | 任务成功不等于抵御攻击 |
| 带合成攻击输入且执行到边界 | 注入入口确实到达、边界决策、最终副作用 | 模型说拒绝不等于没有执行 |
| 检索无命中或工具未执行 | 无命中/未执行的明确原因 | 没看到秘密不等于防御有效 |
| 环境初始化或服务调用失败 | 独立环境错误/不可评估状态 | 基础设施故障不应自动变成安全成功 |
| 防御拒绝了恶意操作 | 拒绝证据、未发生目标副作用 | 轨迹中出现调用尝试不等于攻击成功 |

先用确定性客户端、假工具和合成标记建立机制级测试；只有研究结论涉及真实模型行为时，才在另行批准预算后做模型实验。两类证据不能相互冒充。

指标分别记录：任务完成率、攻击成功率及其分母、拒绝率、无效/环境错误样本数；有真实模型实验时补充调用量、成本、模型配置与重复次数。不用“全部拒绝”获得表面安全分数。

## 4. 与 KoawaAgent 的对应关系

| 已学内容 | 社区可迁移问题 | 当前优先级 |
| --- | --- | --- |
| R3 成功命中前置断言、模型请求检查 | 防泄漏评测有没有真正覆盖成功路径 | 第一题，立即作为教材 |
| R2 model_turn_id 与调用身份 | 重复 call ID 会不会串结果或错误去重 | 第二题候选，不与第一题并行展开 |
| R1 status/resume 重启补发 | 内部方法可用是否等同生产恢复可用 | 第二题候选，偏运行时可靠性 |
| D7 执行账本与 uncertain | 尝试调用、已执行、副作用与未知结果如何区分 | 按首题需要复习，不重读整片 |
| D9 与内容级披露 | 有工具权限是否等于允许披露某个字段 | 后续边界评测，先明确威胁模型 |
| R4 容量门、R5 隔离诊断 | 安全措施是否妨碍正常任务，是否有旁路 | 后续扩展，不纳入首个 PR |

学习遵循“案例提出问题 → 定位实际执行点 → 跑一个反例 → 回看必要概念”。不要求记住全部字段名，不重新逐章通读 D6/D7。

注意：当前代码会继续演进。复现历史问题必须固定旧提交或使用独立最小示例，不在现有工作区回退、覆盖修复。README 和报告只是导航，实际状态须结合提交、代码和实验确认。

## 5. 八周安排

| 周 | 主任务 | 本周产出 | 完成门槛 |
| --- | --- | --- | --- |
| 1 | 确认候选社区；读贡献/安全/AI 使用规则；核对重复 issue；复述本地空转案例 | 一页目标与范围说明、版本锚点、已有讨论清单 | 能解释测试为什么会假通过，以及目标项目是否有对应路径 |
| 2 | 搭建获准的隔离实验；只读跟踪一个 evaluator 或工具结果路径 | 最小运行命令、依赖记录、正常路径基线 | 别人按记录能运行；初始化失败与测试失败可区分 |
| 3 | 补齐最小实验矩阵；验证假设是否成立 | 正反例、原始结果、预期/实际对照 | 目标路径确实执行；结论不只来自模型回复或日志关键词 |
| 4 | 整理最小复现；按社区规则讨论或私密报告 | 可审阅报告草稿；授权后才发送 | 重复项检查完成；影响与未验证部分明确；无秘密和无关数据 |
| 5 | 根据项目范围与反馈做最小测试或修复；暂无回复则打磨本地复现 | 一个聚焦 diff，或可独立运行的测试包 | 确认旧版失败、新版通过，正常路径仍通过 |
| 6 | 补故障路径、反例与回归；自查许可证、格式和提交规范 | 验收记录；授权后提交 PR 或补充证据 | 不靠放宽断言取绿；无关重构不混入 |
| 7 | 处理维护者反馈；将所得经验映射回 KoawaAgent | 反馈处理记录、一条可迁移测试规则 | 能解释取舍；没有反馈就保留待回复状态，不催出虚假进度 |
| 8 | 复盘贡献；整理可公开的案例说明；决定下一题 | 一页复盘、证据包索引、下一阶段选择 | 区分已提交/已合并/未采纳；能独立讲清机制与限制 |

这不是要求每周都产生外部提交。若第 3 周证明假设不成立，记录目标项目如何正确处理，转为补充覆盖或选下一个小问题，不制造漏洞结论。

## 6. 每周时间分配

- 第一天：KoawaAgent 案例复习约 1 小时，整理一个问题；余时缓冲。
- 第二天：目标社区源码与现有讨论约 1.5 小时。
- 第三天：本地确定性实验约 2 小时。
- 第四天：阅读一篇直接相关材料约 1 小时，补反例约 0.5 小时。
- 第五天：整理证据和下一步约 1 小时；其余时间留给复现失败或反馈。

论文不追数量，每周最多一篇重点材料；只回答“它假设什么威胁、如何判成功、正常任务损失多少、我的实验能验证哪一点”。没有直接关系的论文先列入候选，不挤占当前实验。

低精力日最低任务：花 20 分钟写清“当前假设、已有证据、下一次只验证什么”三句话。进度按产物判断，不按累计阅读页数判断。

## 7. 每项贡献的证据包

首题不直接移植整个 KoawaAgent，只携带必要的机制和测试。

证据包应包含：

1. 问题摘要：预期、实际、适用范围，说明是测试缺陷、正确性问题还是已证明的安全问题。
2. 威胁前提：攻击者能控制什么、不能控制什么、哪个可信边界受到影响。
3. 版本和环境：固定提交、依赖、操作系统；真实模型实验记录模型与配置，禁止完整环境变量转储。
4. 最小复现：一个运行入口、合成输入、关键断言，不依赖私人路径或账户。
5. 正反例：旧版失败/修复后通过，正常任务不被无故拒绝。
6. 证据层级：源码推断、确定性测试、真实工具集成、真实模型实验分别标明。
7. 局限：未运行项、跳过原因、已知不覆盖的旁路和恢复组合。

有关安全判断，优先观察实际执行点和副作用；有关数据泄漏，优先观察最终发送边界。读取 Python 对象的部分 .content 字段不能写成“完整 provider 协议序列化已验证”。

## 8. 贡献与披露纪律

- 只在本地隔离环境或明确授权范围测试；开源许可证不等于获准攻击项目维护者的在线服务。
- 使用合成凭据、合成秘密、本地接收端；不向外部服务上传真实数据来证明泄漏。
- 普通缺陷按常规渠道讨论；可利用的安全问题先遵循 SECURITY 或项目指定私密入口。公开 exploit 和披露时间需按协调流程处理。
- 先查重复项和在途修复；已有 issue 可以补证据，但不抢占他人工作或以重复报告刷贡献。
- 遵守项目 AI 辅助贡献政策及要求的披露。Agent 可辅助研究，但提交者须理解代码和证据，不提交未经验证的批量扫描结果。
- 学习其他项目代码、用例或数据时保留出处，核对许可证与署名要求；不假定公开代码可无条件复制。
- 报告中不夸大严重性，不把设计偏好当漏洞，不以“维护者没立即采用”否定项目。
- 每次对外发送前确认目标、内容、版本与披露渠道；当前规划不构成发送授权。

## 9. 停止、调整和验收

应缩小范围的信号：连续两次学习时段仍跑不通环境；复现依赖未获授权的账户或费用；问题已经被上游解决；选题必须同时改多个子系统才能说明价值。此时先记录阻碍，换 mock/最小案例或缩题，不无限扩大任务。

8 周验收：

- 用户能用 5 分钟讲清一个案例：入口、边界、根因、实验、修复及局限。
- 最小案例可重复运行，有正常路径和至少一个防止空转的断言。
- 已完成一次可交付的社区贡献包；经授权则记录外部链接与状态，未授权则停在可发送草稿。
- 至少沉淀一条可以用于 KoawaAgent 的验收规则，不强制立即实现。
- 上游合并属于加分结果，不是由用户单方面可保证的目标；未找到新漏洞也可以产出有效复现、覆盖或澄清。

首个执行动作：与用户一起读“KoawaAgent 检索测试空转”案例，用当前修复版确认前置断言，再只读检查 AgentDojo 的一个评测结果判定路径。开始前重新对齐两边版本，不自动跑真实模型或向社区发送消息。

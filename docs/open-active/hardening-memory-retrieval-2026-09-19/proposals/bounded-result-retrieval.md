# Security Hardening Proposal: 有界历史工具结果检索

## Decision

用户已选择首版关注测试、MCP 等难以重现的输出；MCP 至少要求服务与工具在白名单内；敏感日志不得进入模型服务。测试正文可见规则尚未决定。这里讨论如何让模型找回已有历史线索，以及何时值得扩大留存。源代码有并行未提交修改，实施前须重核。

## Executive Recommendation

选项 1“现有记录的元数据索引”只从已落盘事件提取安全身份和状态，旧正文默认不提供给模型。选项 2“持久化安全投影”在首次工具回执前生成模型可见结果，随后将同一投影按稳定引用保存，供未来检索。这两个选项可前后衔接；对于新回合的实际诊断能力，我推荐选项 2。是否另行长期留存更长原始日志属于本地取证问题，不能靠扩大模型可见投影来解决。

## Current Design And Failure Mode

工具返回由各自 handler 控制长度，账本把结果经过 `redact_text()` 存为 JSON 事件，恢复流也存 `ToolResultMessage` 的脱敏内容。[`execution/loop.py`](../../../../src/koawa_agent_v2/execution/loop.py) 把 handler 的 `result.content` 组成 `ToolResultMessage` 并追加上下文；[`model/openai_client.py`](../../../../src/koawa_agent_v2/model/openai_client.py) 将它序列化为 provider 的 tool 消息。这意味着敏感日志可能在首次回传时进入模型服务，历史检索只是第二次暴露。当前 Session 摘要只得到用户输入和最终回复，CLI `/recall` 查回合并向人打印；模型没有通用的历史工具结果查询接口。即使接上接口，当前请求容量测量漏掉指令与工具定义。正则脱敏只能识别预设形态，不能证明任意日志不含账号、隐私数据或新格式凭证。

## Desired Invariants

- 每条可检索结果有确定的来源：线程、Turn、Run、调用、工具、持久化事件版本、工作区或仓库身份，以及内容摘要。
- 测试与 MCP 原始自由文本在首次回传前通过同一模型入口；无法证明安全的日志只保留本地或提供安全元数据，不进入模型服务。历史读取必须使用相同或更严格的判定。
- 搜索命中不包含原文大段内容；正文读取前验证调用者、线程、工作区和数据可见等级。无法判定的内容只提供安全元数据，不能降级为允许读取。
- MCP 命中须匹配允许的服务、工具和绑定身份；白名单仅证明来源被允许，不能证明返回正文安全。
- 测试 profile 是固定命令身份，不等于 stdout/stderr 的敏感内容等级。仓库策略维护者审查输出契约只建立预期，不能替代运行时内容控制；无法确认等级时仅暴露安全元数据。结构化诊断字段须有明确输出契约及逐次数据检查。
- 每次读取明确报告采集、留存、读取三个阶段是否截断；旧结果不能充当当前代码版本的测试通过证明。
- 检索内容作为不可信数据进入模型；其中的操作指令没有审批效力。
- 最终请求按完整消息和工具定义计量，含输出预留；超过配置阈值就缩小读取或拒发。
- 任何新增持久化只存 JSON，受现有单事件上限、精确 expected version 与 typed event 约束；派生索引可从事件重建。

## Constraints And Non-Goals

首版优先测试和 MCP 结果；历史文件正文快照留待后续。我们不保证能恢复执行器在采集上限之外丢弃的字节，也不把旧回执用于当前交付门禁。外发内容授权是相关但独立的执行边界，检索设计不能取代它。用户没有指定延迟、磁盘与保留期限，容量参数应在代表性长任务上测量。

仅有固定的 `profile_id`、退出码和失败类别，往往不足以完成复杂修复。我们不能把“字段固定”误认为“信息足够”。要同时满足长任务能力和敏感日志不进模型服务，需要按测试**可访问的数据**区分诊断。E5 表明当前 Docker 路径禁网络、只读挂载整个仓库；仓库里若有敏感文件，测试仍能读到，主机 runner 的可达范围还可能更广。事后观察“这次似乎没读”不足以证明没有秘密进入输出。只有把测试放入独立、仅含允许代码与合成输入的工作区，排除凭证、真实数据、敏感文件和网络，并核对运行时实际边界，才有条件将其输出作为详细但有界的模型可见信息。实现前还要检查镜像内置环境和其他数据入口。

对于接触真实数据或敏感资源的测试，模型只能得到固定结构化诊断。若诊断不足，我们可以让模型基于代码提出假设，运行有界的定向安全测试，再观察固定结果。测试本身不能把任意秘密编码进测试名、错误码、路径或可反复询问的真假查询；否则即使没有原始日志，也会形成逐位泄漏通道。若故障只能由不可发送的原始值解释，系统必须明确返回诊断不足。这是能力边界，需要在任务成功率测量中单独统计。

## Before Architecture

[现状图](../diagrams/bounded-result-retrieval-before.mmd)显示工具结果流向当前模型及持久化恢复路径。历史摘要另行进入模型，但没有把具体结果按引用带回。已经落盘的结果可能包含未被模式脱敏识别的敏感文字。

## Options

### Option 1: 现有记录的元数据索引

我们可以先对现有账本或恢复事件建立可重建的短索引，索引只放工具、状态、时间、调用身份、代码版本等经过审查的元数据。旧事件没有可信的“模型可见投影”标记时，不因已脱敏而开放正文。读取服务核对调用者是否仍有该线程和工作区的读取权；等级不明时只返回元数据。首次工具回执仍须另设模型入口，避免新任务继续把敏感日志直接交给 provider。这种方案改动小，但模型只能知道历史曾发生何种调用及成败，无法保证得到修复所需细节。

这条路径的强处是改动面较小，回滚时可关闭搜索入口、重建或删除派生索引，原有恢复事件仍按原用途使用。代价是旧记录只能提供状态和来源，不能因其正文已被 `redact_text()` 处理就向模型开放；该函数只匹配已知格式。性能成本主要来自索引生成与搜索，内存成本由分页和结果数上限控制。实施前需量化事件读取放大与索引大小。

[选项 1 图](../diagrams/bounded-result-retrieval-existing-events-after.mmd)让新增的权限与容量控制位于持久化结果和模型之间。

| Change | Before | After | Security consequence | Cost |
| --- | --- | --- | --- | --- |
| 历史查询 | 无模型可用入口 | 安全元数据短索引 | 旧正文不因已落盘而被开放 | 索引和权限校验延迟 |
| 请求门禁 | 压缩前的部分字符计数 | 完整请求计量 | 防止检索片段挤爆窗口 | 每轮构造后计量 |
| 正文存储 | 现有有界事件 | 不新增可见正文 | 不扩大旧日志的模型可见范围 | 无法找回旧诊断细节 |

### Option 2: 持久化模型可见的安全投影

对于新回合，我们可以在首次工具回执前由可信本地逻辑生成一个有界 JSON 安全投影：在敏感测试中只有固定诊断字段；在确实隔离到可分享输入的测试中可含较丰富的安全细节。投影同时作为首次模型可见结果和未来读取的唯一正文来源，绑定调用身份、工作区、代码版本、策略版本、长度、摘要及截断状态；事件使用精确版本追加，派生索引可重建。模型先搜索安全元数据，再按引用和页范围读取这个投影。原始日志即使留在本地，也不通过该引用向模型提供。

它最有吸引力的地方是让历史诊断与首次回执保持同一可见边界，模型能找回当时确实看过的安全信息。让我犹豫的是投影策略可能判错：如果首次回执已越界，持久化会延长暴露时间。正则脱敏不足以承担允许投影的最终判断，必须由可信本地规则和测试环境约束产生安全投影。运维上还要定义策略版本、保留期限、清理与恢复语义；性能上需要评估额外写入和重放开销。回滚可停止新投影写入和检索，但已落盘数据的处置需遵守保留策略。

[选项 2 图](../diagrams/bounded-result-retrieval-bounded-capture-after.mmd)把新增内容判定放在持久化之前，随后在读取入口再次核对可见等级。

| Change | Before | After | Security consequence | Cost |
| --- | --- | --- | --- | --- |
| 结果留存 | handler 裁剪后的事件 | 首次模型可见的安全投影 | 检索不扩大首次可见范围 | 额外磁盘与写入 |
| 未知等级 | 可能进入已有结果事件 | 投影仅含元数据 | 原始敏感日志不进模型 | 部分结果不可由模型诊断 |
| 读取 | 无模型入口 | 权限、策略版本、分页、预算检查 | 降低跨线程和越界读取风险 | 控制路径复杂度 |

## Comparison

下表方向均是相对现状的预计变化，没有实测性能或成本数值。

| Dimension | Option 1: 旧记录元数据索引 | Option 2: 新回合安全投影 | Basis and validation |
| --- | --- | --- | --- |
| Security | 旧正文不暴露；原有事件敏感风险仍在 | 首次与历史共享模型入口；投影规则出错会扩散 | 源码推断；用敏感样例和跨线程拒绝测试 |
| Performance | 搜索与读取增加数据库工作 | 写入、索引和读取均增加工作 | 假设；比较代表性长任务的 p95 延迟 |
| Memory | 元数据短索引 | 安全投影、索引与写入缓冲 | 假设；测峰值内存和索引大小 |
| Reliability | 依赖事件可读及可重建索引 | 还要处理块与索引的一致性和清理 | 源码推断；故障注入与恢复重放 |
| Operability | 需观察命中率和拒绝原因 | 还需监控配额、期限、清理和分类 | 假设；演练诊断和清理 |
| Migration | 可逐步建立派生索引、关闭入口回滚 | 需新事件类型、历史兼容和数据处置 | 源码推断；旧库升级及回滚演练 |

从这个比较可见，选项 1 适合安全处理旧记录，选项 2 才能为新回合提供可回读的诊断。投影必须先满足“敏感日志不进模型”的约束；更长的本地原始日志存储不自动扩大模型可见范围。两个选项都依赖完整请求容量门禁和读取权限，且都不能替代内容级外发控制。

## Recommendation

我建议旧记录先采用选项 1，默认只提供安全元数据；新回合采用选项 2，把首次工具回执已经通过模型入口的安全投影持久化，随后由检索重复读取相同投影。这样检索不会扩大首次可见范围。我们仍需实测多少故障可由安全投影诊断，多少只能用本地敏感日志解释；后者不能借检索绕过边界。

## Migration And Rollout

先建立首次工具回执的模型入口控制、读取权限和完整请求容量门禁；然后对新回合持久化安全投影，并对旧事件仅建立元数据索引。派生索引按线程分批构建，可从事件重建。对旧事件的敏感级别不能假定为低。灰度期间记录命中率、拒绝率、检索耗时、额外请求字符和诊断不足的任务比例；关闭检索入口可回退检索行为，模型入口控制继续保留。更长的原始日志留存另行评审，不与本次投影变更混在一起。

## Validation Plan

验收样例包括：带敏感值的测试日志在首次工具回执及历史检索中都不进入模型请求；跨线程或跨工作区引用被拒；未知敏感级别只返回元数据；工具结果中的伪指令不提供授权；已裁剪的结果明确标记不完整；旧测试通过不能通过当前交付门禁；搜索和读取不会绕过最终请求容量限制。基准任务覆盖短输出、长失败日志、MCP 返回、中文文本和多轮检索。量测任务完成率、找到关键失败原因的比例、额外存储、p95 检索耗时、模型输入及缓存用量、总重试轮数。没有预设百分比目标，阈值应在首轮基线测量后与你商定。

## Implementation Work Packages

这些是设计审查的依赖顺序，不授权实施：定义结果身份与可见等级；补完整请求门禁；实现可重建短索引及权限校验；实现分页读取与截断说明；做跨边界与长任务验证；按结果决定是否扩展留存。

## Open Questions

首版 MCP 来源门槛已经确定为服务、工具白名单；还需绑定身份校验与模型入口的数据策略。测试输出暂按 profile、状态、退出码、代码版本、截断标记建立元数据索引。仓库策略维护者可审查 profile 的预期输出契约；即使通过审查，每次结果仍须检查内容。原始自由文本日志不得进入模型服务；模型可用的安全结构化诊断格式、日志在本地的保留期限，以及内容级外发控制与检索读取的共同数据标签尚未定。用户已明确历史文件正文快照不属首版优先项。

## Executive Recommendation

我们考虑了两个可衔接的选项：选项 1“只检索旧记录安全元数据”适合历史兼容，也可在资源不足时独立使用；选项 2“安全投影、按需检索与接收方授权”覆盖新任务的完整诊断链。我们采用选项 2，并把选项 1 作为旧记录迁移规则。

完整流程是：工具在本地运行，可信适配器决定哪些信息可以发送给当前模型服务；安全结果以固定身份发布，首次回执与以后检索共享同一份内容；摘要只保留任务线索和引用；模型需要时先搜索再读；新的完整请求在发送前统一检查；如果模型还要把结果交给 MCP 或上传工具，则按那个接收方重新授权。原始私有日志没有通往这些模型入口的自动通道。

这个选择增加了本地存储、权限检查和故障恢复工作，但能避免把“结果已落盘”“曾发给模型”“工具在白名单”分别误认为内容可公开的证明。我们不承诺隔离能消除全部漏洞，也不承诺任意敏感故障都能自动诊断；无法安全提供关键事实时，任务应明确报告诊断不足。

## Current Design And Failure Mode

当前工具可以把结果作为 ToolResultMessage 追加到模型上下文。即使账本经过 redact_text，正则也只能识别既定格式，无法证明任意正文不含私有信息。测试输出在首次回执就可能越过模型服务边界；以后增加检索会扩大可再次接触的范围。旧结果已经进入事件流，不能靠给新索引加“安全”标签改写其历史来源。

D9 已对具体动作身份和批准进行绑定；我们应复用这些机制。缺少的是“这个负载允许给哪个接收方”的数据契约。把受限内容复制进 MCP 字符串参数后，原结果对象上的标签不会自动传播；仅扫描已知秘密形状或依赖模型声明，无法解决任意重编码和拼接。

F20 的零 seed 结论已由 E10 撤回。实际 seed 有六项，首次压缩事实已写入，后续压缩映射失败；具体触发机制仍需复现。本设计要求核对内容身份、保护边界及替换后的来源映射，不能只比较项数。空 seed 与非空 loop 可作为防御性测试，但不能冒充该事件的已证实根因。

## Desired Invariants

- 每个模型可见内容项均有可信来源及当前模型接收方的许可；首次回执、重放、压缩模型输入、搜索和读取遵循同一边界。
- 未知或敏感原始日志不进入模型；固定字段也必须有可信来源和允许释放的含义，不能任意回显错误正文、文件名或实际值。
- 保密性与指令可信度独立：允许模型看见的工具结果仍是不可信数据，不能产生批准或扩大能力。
- 结果引用只标识对象，不授予权限；调用者、线程、工作区、接收方和策略必须由执行上下文核验。
- 新结果历史正文严格来自已发布的首次回执安全投影；旧记录正文不因已落盘、已脱敏或过去曾可见而自动开放。
- 历史测试只证明当时的执行；交付检查读取可信证据并重新核对当前候选版本，不接受模型引用或口头结论代替。
- 最终请求计量覆盖实际发送的全部模型输入与输出预留，不能依赖是否触发压缩。
- 内容外发必须在实际发送前绑定不可变负载和最终接收方；MCP 白名单、用户泛化批准、检索权限均不能代替。
- 执行结果、投影可用性、索引可用性是不同状态；索引失败或投影缺失不得触发有副作用工具的重新执行。
- 新持久化仅使用 JSON 和有类型事件，权威状态写入使用精确 expected stream version；不保存凭证字段、隐藏推理、进程句柄或环境快照。

## Constraints And Non-Goals

首版聚焦测试与 MCP 结果，不建设历史文件正文快照或向量数据库。我们保留标准库与现有存储为主的实现路线；本地索引先用结构化字段过滤，不把私有文本交给外部嵌入服务。全仓安全问题、C7/C8 的 worktree 投递与清理设计不随本方案自动关闭。

用户优先选择敏感信息边界，同时希望长任务可完成、成本可控。任何性能或任务成功率提升在本次都未实测。Docker runner 改造属于详细诊断的前置工作包，不能在改造完成前对外宣称“测试日志已安全”。

## Options

### Option 1: 旧记录仅提供安全元数据

我们从旧事件中重建工具类别、可信调用身份、已知执行状态等经过字段策略允许的索引项。旧自由文本、错误摘录、原始路径、用户自定义标题不能顺便进入索引预览。查询只返回当前调用者可见的候选，不以拒绝信息泄漏其他线程的记录存在性。

该选项能帮助 Agent 找出“之前是否运行过某个测试”，兼容性好，派生索引损坏后可重建。它无法恢复被丢弃的详细诊断，也不能把旧记录升级为安全正文。模型入口和请求容量门仍是必要前置；否则新结果仍会沿原路径越界。

成本主要是事件扫描、索引占用和查询；按水位增量构建、限制扫描工作量即可避免每次搜索全量回放。关闭读取入口可回退，安全入口仍保留。如果实测显示只有状态信息已足够完成目标任务，这个选项可作为独立较小交付。

[选项 1 图](../diagrams/bounded-result-retrieval-existing-events-after.mmd)展示旧事件只能通过安全元数据进入模型。

| Change | Before | After | Security consequence | Cost |
| --- | --- | --- | --- | --- |
| 历史搜索 | 无统一模型结果入口 | 受权限约束的安全元数据索引 | 不开放旧正文 | 索引和查询 |
| 首次与恢复入口 | 长度与模式控制 | 同一可见性门 | 阻止未经分类日志自动重放 | 适配旧记录 |
| 最终请求 | 部分容量测量 | 完整发送前检查 | 检索不能绕过容量 | 计量工作 |

### Option 2: 安全投影、按需检索与接收方授权（已选）

我们保留选项 1 的旧数据规则，为新结果引入可信适配器产生的不可变安全投影。完整设计如下。它增加了运行时责任，但每个边界都有独立可测试的契约；不依赖模型记住“不要泄漏”。

#### 1. 私有结果与模型诊断双通道

本地执行器先得到结果，受信任适配器按实际执行配置选择诊断路径：

| 运行条件 | 可生成的模型内容 | 不充分的证明 |
| --- | --- | --- |
| 隔离执行只可访问已准许给该模型的代码、合成输入和依赖 | 有界断言、堆栈、源位置、合成值等详细诊断 | 仅有 Docker、固定 profile 或测试自报“安全” |
| 接触真实敏感资源，或可达性未知 | 经审查的固定释放契约所允许的状态；没有契约则仅诊断不可用 | 固定 JSON 字段、正则没命中、事后未观察到读秘密 |
| MCP 来源与绑定获准，输出字段有契约 | 合同允许的字段或明确允许的正文 | 来源白名单本身 |

测试 profile 由仓库策略维护者维护其命令、输入范围和输出契约，runtime 核验每次实际运行证据。模型不能修改 profile 后继承旧批准；内容或配置变化产生新摘要，需重新满足策略。审查是策略所有权，不新增一个独立审批组织或服务。

安全测试工作区必须从允许清单复制固定版本文件，不直接挂载整仓库；处理符号链接、硬链接和宿主路径穿越，排除 .git 凭据、真实数据、主机环境与凭证代理。镜像和依赖按身份固定，检查内置环境及挂载；运行时禁网络、无宿主 socket、设备或未批准卷。模型修改过的测试仍是任意代码，隔离必须靠执行环境保证。

代码本身可能包含业务秘密。允许它进入此测试工作区前，必须已允许交给目标模型服务；“合成数据”不等于源码公开。任一数据入口无法核验，退回受限诊断路径。

受限诊断默认不允许模型对真实秘密反复运行任意条件测试。即使每次只输出成功/失败，也可能成为逐位查询接口。固定释放契约应规定谁可运行、可运行哪些固定测试、可释放哪些事实以及累计调用约束。已有秘密接触不能通过稍后执行一个“安全测试”洗成可见内容；安全重测必须在新隔离环境中使用合成数据。

原始输出默认只在本地受控内存缓冲中短暂存在，不自动进事件、摘要、trace、异常或模型。双通道不意味着永久保存完整原始日志。首版不新增任意原始日志持久化；既有含敏感内容的历史数据另做隔离与清理。需要本地取证时，后续策略仍不得违反不持久化凭证字段的仓库规则。

##### 敏感测试容器的具体约定（2026-09-21 已选，待实现）

用户已接受下列执行方案。我们把大部分编码和调试安排在合成输入环境，敏感环境用于受控验证；不要求用户批准每一次正常临时写入，也不让模型通过扩大挂载或读取产物绕过回执限制。

| 区域 | 权限与准备方式 | 结果处理 |
| --- | --- | --- |
| 本次候选代码、测试脚本、依赖 | 固定版本，只读；按 profile 输入清单准备 | 任一内容变化产生新的候选身份，不能继承不适用的批准 |
| 必要敏感输入 | 经授权的最小文件集合，只读；优先固定快照或可验证版本 | 未知或敏感输入使整个运行及其派生产物保持受限 |
| 专属临时目录 | 每次运行独立、可写、有资源上限；首选临时内存文件系统，不映射宿主项目 | 测试数据库、缓存、日志、截图、报告、压缩包及崩溃文件全部视为敏感 |
| 其他宿主目录、设备、socket、网络 | 不提供；禁宿主网络、凭据代理及共享可写缓存 | 不存在直接外发通道；不能通过宿主 fallback 恢复这些能力 |

profile 提供初始输入范围，模型可提出缺少依赖的需求。运行时只在已授权范围内扩展清单，超出范围则返回需要新增输入授权的固定状态；不能自动挂载父目录或整仓库。目录是选择入口，最终授权对象是解析后的具体文件集合、版本和目标挂载位置。目录中新文件不自动继承可分享资格。复制或挂载准备须防止链接逃逸及检查后替换；只读挂载本身不冻结宿主写入，因此输入变化无法排除时，测试证据标为不稳定，不用它证明固定候选通过。

临时写入属于 profile 的常规能力，预授权后不逐次询问。敏感环境内生成的文件不自动同步回工作区、不进入结果索引、不提供通用 read_file 接口，也不作为下一次安全测试的缓存。运行结束或失败后均由受信任运行器清理；清理失败就隔离该运行的暂存区，禁止复用，并记录不含敏感路径/正文的状态。磁盘、内存和保留时间取实测配置；不声称普通文件删除能完成物理安全擦除。

原始敏感产物默认不长期保留。确有本地取证需求时，只能进入独立受控流程，继续遵守不持久化凭证字段的规则；不能凭一个“保留产物”批准把所有输出永久写入账本或宿主。需要对外提供诊断时，由可信适配器产生一个新的获准版本，不能改原产物的标签就开放全文。

新增敏感输入范围、写真实数据或导出产物分别需要具体授权，不能合并成“容器获得更高权限”。当前 profile 内的临时写入无需额外批准。修改真实数据不是本测试 profile 支持的动作；另走业务操作的策略与账本。外发由容器外的受信任适配器处理，并绑定固定内容和接收方；不在敏感容器里临时打开网络。审批不能覆盖用户既定的“敏感日志不得进入模型服务”约束。

输出限制覆盖正文之外的文件名、路径、测试名、附件说明和可见错误文本。受信任运行器可以知道详细执行事实，但模型只获得释放契约允许的字段；“系统本地知道结果”不等于“模型可以读取结果”。耗时、输出大小等也不默认全部回显，隐蔽通道仍需在威胁范围中明确。

敏感验证绑定候选代码、测试/profile、输入版本和环境摘要。模型改待测代码同样可能构造秘密真假探测，因此固定脚本和有限次数均不能单独证明安全。策略必须定义允许验证哪些候选、是否要求候选审查、允许向模型释放哪些事实；未具备此契约时不开放模型可观察的敏感验证。重复调用、换候选、换 turn 或恢复不能重置任务的数据披露预算。已完成执行优先复用可信状态，unknown 仍走 D7 恢复，不为取得更多日志重执行。

当受限结果不足以修复时，模型在全新、无敏感输入且不复用敏感产物的容器中尝试合成复现。仍必须依赖真实秘密才能解释的故障，明确报告诊断不足并交给本地人工处理。我们不以承诺“绝不阻塞”来降低输入、回执或外发约束。

##### 测试依赖准备流程（2026-09-22 已确认，待实现）

用户确认采用自动发现与隔离试跑辅助准备依赖。维护者负责批准资源类别和访问边界，无需手工枚举每条导入关系。“测试需要某项资源”的发现结果不产生访问该资源的权限。

流程：从项目配置、锁文件、测试入口、夹具和已有 CI 配置生成候选依赖清单；准备不含敏感数据的隔离环境；通过静态分析与试跑定位缺失项；在已授权范围内自动补齐代码、依赖、配置及合成数据；超出范围的敏感目录、凭证、外部服务需要单独授权；最后将验证后的命令、输入范围、运行时/镜像、依赖身份、变量白名单和服务配置固定为 profile。变更这些内容时重新检查受影响部分。试跑与静态分析不能证明依赖清单完整，动态加载或条件分支仍可能在后续运行暴露缺失。

第三方依赖在独立的受控准备阶段从允许来源安装并固定身份；该阶段同样执行不可信安装/构建代码，不能携带敏感输入或宿主凭证。敏感测试运行时不联网补包。临时数据库等服务优先使用合成数据；如需容器间通信，应另有明确隔离策略，不能默认放开当前禁网络边界。缺失真实数据文件优先尝试合成替代，不因程序尝试读取它而自动批准真实数据访问。

依赖补齐的次数、耗时与资源消耗受有限预算约束，数值留待实测。补齐失败提供安全的缺失依赖状态，不回退整仓库挂载、宿主运行或无限网络安装。依赖准备与结果披露分别受权限约束；回执原则的最终确认状态见下节。

##### 四份回执约定（2026-09-21 讨论，2026-09-23 确认状态校正）

本节最初应用户要求作为讨论稿记录；按用户明确的“下一部分即确认”规则及后续取舍，职责与回执原则现为已确认、待实现。每个真实 profile 的具体输入与释放字段属于待配置实例，不是架构方向仍待裁决。这里只讨论职责、数据流与接口含义，不要求读者关注 Python 类或函数。

**约定一：测试 profile 决定本次允许做什么。**它绑定测试集合与候选代码，声明可读敏感输入、临时写入范围、禁止访问的资源，以及允许向模型释放的结果。范围内的常规运行不反复审批；缺少依赖可以在已授权范围内自动补齐，需要新敏感输入时只暂停相关验证，其他独立的安全测试仍可继续。维护者还要定义候选代码准入规则：模型改变业务代码同样可能构造秘密探测，不能因为测试名称未变就无限继承敏感数据访问权。不满足准入规则的候选需要本地审查。

**约定二：运行器记录实际发生了什么。**本地事实包括是否启动、进程是否退出、退出码、是否超时、使用的输入版本和清理结果。运行器直接观察到的事实不被测试 stdout 中的“成功”覆盖。环境未准备好、测试未完成与测试发现业务错误分别表示；工具执行完毕不能推导测试通过。本地可记录的事实并非都允许向模型披露，后续仍须经过释放规则。

**约定三：回执生成器只执行明确允许的事实转换。**它使用可信的本地规则，不把敏感日志交给另一个云端模型进行“安全判断”。如果 profile 只允许释放指定验证的通过状态，就不附客户名称、实际值、预期值、差值或原始报错。测试自定义文本、错误码和产物不能直接成为可信回执。没有业务结论释放权限时，只有执行完成状态本身也获准披露，才可以返回“执行已结束，详细结果仅供本地查看”；否则使用该契约允许的固定不可用状态。

已确认的核心规则：敏感测试的“通过/未通过”不隐式公开，由每个 profile 明确授权。普通安全测试提供详细诊断；敏感验证优先按明确授权返回总体结论，有限诊断类别另行配置。通过状态本身可能泄漏信息，需要同时确定候选准入和重复验证规则。固定字段与调用次数限制均不能单独证明安全。禁止披露时转人工，不作为常规调试反馈。

**约定四：模型回执明确当前状态和可行下一步。**建议的字段含义如下，具体序列化字段名留给实施阶段：

| 回执内容 | 允许表达的含义 |
| --- | --- |
| 执行状态 | 已完成、未完成或不确定；该状态自身也需符合释放规则 |
| 验证结论 | 仅在获准时展示通过/未通过；否则明确不可提供，不能伪装成失败 |
| 诊断可用性 | 有安全诊断或诊断受限，不附受限原因中的敏感细节 |
| 记录引用 | 绑定真实执行记录；引用本身不给正文读取权限 |
| 可用后续动作 | 仅列当前策略实际允许的合成重测、环境修复后重试或本地处理 |

示例：在执行状态和验证结论均获准披露的 profile 下，可以返回“测试已完成；结论为未通过。详细诊断受限，可在合成数据环境中继续定位”。不能把这个示例当成所有敏感测试都可使用的默认回执。后续动作来自运行时允许范围，不采纳日志中的伪指令；执行结果 uncertain 时不能直接建议重试，仍依赖 D7 恢复证据。

下一步工作是为具体测试 profile 填写允许事实与可信生成方式，不再重复询问是否按 profile 授权这一原则。没有相应配置与权限事实时，本节不构成对真实敏感数据的新增执行或披露授权。

##### 敏感验证的候选准入（2026-09-23 已确认，待实现）

用户已确认：合成环境充分自动化，敏感环境按固定候选做阶段性验证；自动准入限于维护者预先授权的范围。这次确认不等于已经实现，也不自动批准任何真实敏感数据或外发接收方。

模型先在合成数据环境完成一批修改和详细测试，再提交固定候选。候选身份绑定实际代码、测试脚本、依赖、镜像/运行配置、敏感输入版本和 profile；不能只绑定分支名、路径或 generation。输入无法固定或校验稳定时，不宣称验证针对确定候选。

准入规则由维护者预先定义。运行时检查测试判定、数据访问范围、依赖和执行配置等是否超出规则；满足既定权限的流程可自动运行，超出范围的候选交给本地审查。对任意新代码接触高敏感数据且向模型返回结果的场景，默认先审查固定候选。检查改动路径或用模型审查只能辅助筛查风险，不能证明业务代码没有通过结果传递秘密的逻辑。

批准绑定候选与策略版本；批准后代码、测试、依赖、输入或环境变化时，原批准不适用，重新走准入。执行前核验固定对象，不能审查一个版本却运行另一个版本。默认批量审查阶段性候选，不要求每次合成环境修改都审批，也不把一次候选批准变成后续任意版本的长期通行证。

敏感验证结果仍按该 profile 已确定的信息释放契约返回。准入批准与结果披露是两个条件，不能互相替代；上节回执原则已确认，具体 profile 的允许字段需要按部署配置落实。已完成且身份匹配的调用优先按可信账本复用；unknown 先按 D7 核实，不能为获得结论盲目重跑。改候选、换 turn、恢复或重复提交不得重置任务累计披露限制，具体阈值留待实测。

这种安排把正常迭代留在合成环境，把必要审查集中到阶段性候选。对不能安全自动准入的敏感任务，系统应保留本地审查或诊断不足的出口，不承诺自动检查可以消除所有语义泄漏风险。

##### 自动修补与人工验证的取舍（2026-09-23 已确认，待实现）

用户确认：日常修补尽量在合成环境完成；“结果不可提供”只作为确实禁止披露时的停止信号，不作为正常调试回执。若安全可用信息不足以完成任务，则交给人工测试与处理，接受相应的自动完成率损失。这一决定明确了前述四份回执约定的停止语义，具体 profile 的允许字段仍需落实。

| 路径 | 模型反馈与后续动作 |
| --- | --- |

模型可见示例：“该验证结论不向模型公开。不能据此判断补丁通过或失败，也不要因此修改补丁；后续敏感验证交由人工处理。”提示不确认未经允许披露的执行细节。能够独立完成的安全工作可继续；依赖隐藏结论的部分明确待人工验证，整体不能宣称全部测试通过或任务已完整交付。

人工交接提供当前固定候选的安全身份、已完成且可公开的合成测试证据、尚待人工验证的事项，以及获准的本地处理入口。原始敏感数据和隐藏结论不经模型转交。不得将结果不可提供映射为测试失败，不触发自动改补丁或为探测结论重复敏感测试；D7 执行状态与模型披露状态分别保留。

人工后续可以提供获准的脱敏说明，或按既定规则确认固定候选的验证结果。任何补充信息仍经过模型入口策略；人工处理不自动解除敏感日志禁入规则。泄漏后采用保守的暂停、本地检查与安全重建；不做首版自动无损清洗，详见保留、撤销与审计章节。

##### 测试快照与交付证据（2026-09-23 已确认，待实现）

每次测试绑定固定输入快照，包括代码、测试脚本、依赖、运行环境/profile 和输入数据版本。独立测试工作区须记录该身份，并与原有 generation、文件哈希及验证证据关联；不以相同路径或相同测试名继承旧结果。

例：H1 测试失败，模型修改得到 H2，H2 测试通过，随后用户修改为 H3。H2 的成功仍是真实历史，但不能证明 H3 已验证。交付前可信检查必须核对当前候选与测试证据的绑定；不一致时重新验证或明确当前版本未验证，不由模型口头结论放行。

测试候选代码只读，生成文件写本次临时区。需要代码生成或编译时，显式记录构建输入及产物身份，测试证据说明实际运行了哪个产物；不能悄悄修改候选后仍报告原版本。工作区并发变化不改变已冻结快照的历史结果，但可能使其不再适用于当前交付。固定快照是可重复和可追溯的条件，不承诺外部环境或非确定性因素天然相同。

##### 测试缓存复用（2026-09-23 委托定稿，待实现）

用户授权由设计方敲定缓存细节。首版采用受控依赖缓存、安全构建缓存和敏感运行临时产物三类，规则如下：

| 类别 | 准入和身份 | 可见性与写入 | 失效和回退 |
| --- | --- | --- | --- |
| 依赖缓存 | 无敏感输入的受控准备阶段生成；绑定运行平台/架构、运行时/工具链、依赖锁定结果、来源与内容摘要 | 经当前访问策略允许后，只读使用；包的安装钩子仍是不可信代码 | 身份不匹配、来源未知或完整性失败视为未命中，进入受控准备阶段，不在敏感测试容器联网安装 |
| 安全构建缓存 | 绑定实际源文件集合及内容、依赖、镜像/工具链、构建命令与配置、允许的影响构建的环境；来源必须无敏感输入 | 默认限定项目和授权范围，只读复用；私有源码产物不因无真实客户数据而公开 | 无法枚举影响构建的输入时不启用共享复用；候选不匹配时重新构建，不借路径相同或 mtime 相同命中 |
| 敏感运行产物 | 接触过敏感输入或来源未知，包括运行期间形成的缓存/数据库/生成文件 | 首版不发布至跨运行缓存，只存在本次受控临时区 | 按运行清理规则处理，绝不供后续合成测试复用 |

共享缓存只由受控发布器写入。测试需要写缓存时使用本次私有覆盖层或临时目录，不修改共享对象；不自动把该写入合并回共享缓存。敏感测试可以读取已允许的只读依赖或安全构建产物，但其中产生的新增文件、运行缓存和变更均归本次敏感产物，不能回流共享区。

发布前在暂存区完成内容及来源检查，以不可变身份原子发布；权威发布/撤销状态遵守 typed event 与精确 expected version。并发构建不得暴露半成品，崩溃留下的未发布对象不可命中。读取时校验当前权限、manifest、对象身份和完整性；发现损坏或撤销后停止使用并隔离，不能盲信模型提供的缓存键。缓存命中本身不向模型开放产物正文。

缓存可被回收，不能是唯一测试证据。缺失缓存只影响性能，不改变测试结论；已在用对象通过运行生命周期引用保护，禁止清理时删掉活跃挂载。采用依赖闭包不完整的缓存会误用旧构建，因此不确定时选择重建。磁盘/时间配额和回收参数经真实测试选定，不预设数字，也不复制完整宿主环境作为缓存键。

复用安装或编译结果不等于测试通过，不新增跨版本免测试路径。每次测试仍绑定当前快照及实际使用的构建产物身份。验收必须覆盖敏感缓存流入合成环境、可写共享缓存污染、不同平台/依赖误命中、未发布半成品、撤销后读取和回收活跃对象等反例。

#### 2. 可见性与来源数据契约

我们不采用单一的“public/private”开关。安全投影的可信元数据区分：

| 字段组（拟定） | 含义 |
| --- | --- |
| identity | 不透明 result_ref；thread/turn/run/call 身份；事件流和版本；工具与绑定摘要；仓库/工作区身份 |
| execution | ledger 状态、工具 is_error、测试退出码和可信测试结论分别表示，禁止互相推导 |
| applicability | 代码内容基线、测试 profile 摘要、环境/依赖身份、验证证据引用；不适用或未知时明确为空并附状态 |
| visibility | 输入类别、投影契约版本、允许的模型接收方、外发接收方限制；由可信运行时赋值 |
| integrity | 投影版本、规范化 JSON 摘要、来源证明引用；原始秘密摘要不对模型公开 |
| completeness | 采集截断、投影删减/截断、当前读取截断、留存可用性分别记录 |

输入类别至少区分 unknown、restricted 与 isolated_shareable；它们是运行时判定的来源条件，不是模型可自报的升级标签。可发送给某个模型服务不代表可发给全部模型服务；切换 provider/账户/部署前重新核验。外发权限同样按接收方和用途表达。被批准阅读的文本仍带不可信内容身份，投影不得把其中“系统指令”提升成运行时指令。

引用采用不透明随机标识，持久化为字符串供查找。它不是可单独使用的 bearer capability；即使模型猜中或拼接出引用，每次读取仍检查可信执行上下文。完整证据摘要、内部路径与秘密的哈希不会为了方便展示而全部返回给模型。

#### 3. 发布、首次回执与恢复的一致性

“相同安全投影”在本版有精确定义：持久化的正文等于首次工具回执获准展示的规范化安全内容；以后可以按页重复读取它，但不能从原始日志里补出当时没有发布的额外正文。首次回执超出容量时，先形成一个更小但明确截断的投影，再固定其身份；丢弃部分不可借分页找回。未来若要保存更长的独立安全诊断产物，需显式扩展契约，不能悄悄改变本语义。

我们采用“不可变 JSON 正文＋有类型发布事件＋可重建索引”。正文存于本地受控投影存储，以安全投影摘要校验；事件保存引用、状态与必需的可信元数据，不重复保存大段正文。这样既能保持 JSON 持久化，也能在过期后清理正文而保留审计状态。新的回执/恢复事件引用该正文与安全占位信息，不能继续复制原始 stdout/stderr。

发布顺序是：保存工具执行终态和可信事实；生成安全投影；写入不可变正文并校验；以精确 stream version 追加发布事件；形成首次回执；再更新派生索引。跨存储无法原子提交时，发布事件是可见性的提交点。正文写成功但事件失败的对象是不可见孤儿；事件已提交但索引失败时可重建，不能再执行工具。

若工具已成功而投影生成或保存失败，保留原执行状态，记录投影不可用，只返回获准的固定状态。不能把“读不到诊断”改成“执行未发生”。重启后从已提交的投影重放，不重新调用工具或模型摘要来猜测结果。

新投影有 published、revoked、expired、corrupt 等可用性状态；索引另有独立水位。撤销和过期先落 typed event、撤销可见性，再删除正文；中途崩溃不恢复访问。清理同时覆盖副本、派生索引与备份策略，不能声称删除单个文件就物理擦除了所有副本。

#### 4. 搜索与读取接口

拟定两个只读工具：

- search_tool_results：按允许的工具、测试、结果类别和时间范围搜索安全元数据，返回有限候选与游标。
- read_tool_result：按 result_ref 与游标读取同一不可变投影的一个有界片段。

thread、principal、workspace 从可信执行上下文取，不由模型参数选择。首版仅允许当前线程/工作区内有权的记录；跨线程共享与子 Agent 共享须经单独产物转交机制，不能凭父子关系自动开放整个历史。

首版采用结构化索引，不向量化原始日志。模型可见标题和错误类别来自可信允许列表；不对未知正文生成摘要、embedding 或“前几行预览”。查询本身不因只读就自动写入无限增长事件；预算消耗、审计和游标状态若持久化，仍遵守 typed event/CAS。

游标是服务器签发的不透明值，绑定查询、结果身份/版本、权限范围、排序水位、位置和有效期；不能把裸 offset 当权限。每页重新核验权限和策略，策略变化不沿用旧许可；不得通过页拼接、重复第一页或新建 turn 绕过累计配额。服务端按 thread/task 与调用者统计累计读取，缓存命中也计入披露量。

搜索结果说明索引水位与是否完整；索引缺项不能宣称“从未执行”。索引损坏可重建或返回暂不可用；不得回退到暴露原始事件。引用不可见和不存在对无权限调用者提供统一的 result_unavailable，避免存在性探测。

#### 5. 摘要、保护组与检索如何组合

摘要承担任务方向、未解决问题和重要决策，不把每条工具输出都永久塞进前缀。运行时从真实已发布结果绑定证据引用；模型可建议引用，但必须解析到同作用域的真实记录，不能生成一串看似可信的 ID 就进入证据区。

例如摘要可以写“令牌过期校验曾在 H1 失败，P1 后在 H2 通过”，同时附运行时验证的诊断和测试引用。叙述仍是可有误的摘要，引用才提供返回源记录的入口。再压缩时允许减少正文和引用数量；当引用离开上下文，结构化搜索仍能找到保留期内的记录。未找到或正文过期必须明确，不补写历史事实。

滚动摘要与近期窗口共同受预算控制。历史用户消息并不永久豁免：可以在保留耐久原始输入的前提下，按显式会话投影规则压缩已完成历史；当前用户请求、未完成工具协议组和当前有效约束不得默默丢弃。约束抽取有歧义时保留原文或声明容量不足，不能自动扩大任务权限。

缓存策略采用稳定指令/工具定义前缀、较稳定的长期摘要、近期消息和按需结果后缀。仅在达到触发条件时合并最旧摘要；不为追求命中率保留越权数据，也不在每次查询中注入变化时间戳。工具目录变更必须更新真实绑定，即使损失缓存。缓存命中收益需真实 provider 统计，不能根据字符重合自行宣称。

#### 6. 完整请求容量与成本

最终发送门位于工具快照和全部消息确定之后，在 provider 请求发出之前。计量范围包含系统/开发指令、用户消息、摘要、工具调用及结果、检索片段、工具 schema、协议包装开销以及输出预留；有图片等内容时必须使用对应模型的计量规则。

软阈值用于提前压缩和选择检索范围；硬阈值负责最后拒发，两者独立。短消息、无可压缩组、关闭压缩、恢复、换 provider、扩大工具目录等路径均不能跳过硬门。官方 tokenizer/计量器可用时优先使用；否则采用经过验证的保守估算并明确误差，未知配置不能按零开销计算。

超限时依次缩小未发布的读取范围、移除可再次检索的历史正文、合并允许压缩的历史；每步后重建并重新计量同一工具快照。仍超限就返回 context_capacity_exhausted，保留执行进度，不发送超限请求。不能为了塞进窗口破坏 call/result 配对或把失败事实压成成功。

模型最大窗口是上界，日常目标窗口应由任务完成率、诊断信息保真、额外调用、缓存用量和总成本共同选择。参数见实施交接的实测表，本文不提供页大小、总页数或累计读取默认数字。

#### 7. 历史证据与当前交付

历史结果至少绑定当时的代码基线、测试配置和可得的环境身份。我们明确区分执行器成功运行、测试退出码为零、规定测试集合通过、当前业务逻辑正确；任何一项都不能自动推出后续各项。

首版保守选择：跨 turn 检索到的旧测试用于推理，不自动升级为当前候选版本的交付证据。现有机制若在同一执行身份下合法复用账本/回执，继续遵循其原有可信校验；检索工具不新增通过路径。未来跨 turn 免重测复用须单独定义输入闭包、profile、依赖、环境与候选版本等价性。

交付门读取可信记录，不解析模型最终回复来认定通过。代码变成 H2、测试配置变化、测试自行修改工作区、环境未知或结果 unknown 时均不得靠 H1 的成功记录放行。相同 generation 不是完整内容身份，相同文件哈希也不证明测试环境相同。

#### 8. 内容级外发控制

外发接收方包括 MCP 服务、上传工具、外部 URL、远程搜索等收到请求参数的系统；即使工具被称为“只读搜索”，查询参数也会传出内容。模型服务本身由前述入口门控制，其他接收方由执行层外发门控制。

默认采用 export_artifact_ref＋destination_ref。模型选择引用，可信适配器读取固定版本、已获准向该接收方发送的产物，生成实际请求。模型生成的任意报告即使经过类型校验，也不自动成为可外发产物；只有可信字段投影、明确的来源许可或对固定版本的本地审查才能赋予资格。首版不提供任意自由文本外发的通用快捷通道；已有此类工具须受同样规则或在受保护模式禁用。

门禁顺序是在副作用发送前：解析固定产物与接收方，核验当前策略，构造完整不可变负载，计算动作摘要，完成现有 D9 授权/必要批准与 D7 claim，再在实际发送处核验相同负载、接收方、绑定和批准仍有效。已有执行器内部顺序可按事务契约实现，但不得在最终检查前发送任何字节。

授权绑定工具/服务及 MCP 会话与 schema 身份、账户/租户/项目、规范化目标、实际负载摘要、产物版本和策略版本。检查包含 URL path/query、headers、文件名和 MCP arguments 等所有承载内容的位置；认证由受控凭据服务注入，凭据值不进入持久化摘要文档或模型上下文。默认拒绝自动重定向到新目标；DNS、地址或连接身份改变需要重新确认原策略仍满足。

用户批准只在策略允许 ask 的动作上使用。它不能覆盖“敏感日志不进模型”的硬性规则；“上传报告”的泛化批准不能替换绑定到固定负载的授权。产物在批准后变化、地址换账户、MCP 更新绑定，都必须使旧批准不适用。

MCP 服务可能在收到请求后再转发；客户端白名单不能证明服务器内部行为。接收方政策需把该服务本身视为已经收到全部参数，服务端下游行为只能通过受控部署或独立契约约束。任意 shell、测试网络、插件直连等旁路必须纳入同一执行边界；无法控制的出口存在时，不宣称内容级外发保证。

发送后超时仍是 uncertain，按 D7 证据恢复；重新批准不证明前一次没发送。外发门解决是否允许发送，账本解决已经发送或可能发送后的状态，两者不能互相代替。

#### 9. 保留、撤销与审计

投影留存期限和磁盘配额通过实测配置；未配置完整有限边界时不启用生产检索。我们保留最小可信执行事实用于恢复和交付，详细诊断可过期；过期后引用仍能诚实返回“正文不可用”，不能默默指向另一个结果。

若发现投影误含敏感内容，立即按策略撤销后续读和外发，标记受影响版本，隔离正文与派生索引，记录不含秘密的事故事实。撤销不能撤回已经发给模型或服务的数据，需要承认该限制。审计只记录安全引用、规则编号、决定、大小和必要版本；不把被拒负载、完整异常、环境或秘密散列复制进日志。

##### 清理与异常处置的已确认边界（2026-09-23 状态校正）

产物清理方案已确认：正常结束、失败或取消后，先登记可持久化的执行证据与获准回执，再清理敏感临时产物；未获准的原文不因取证而自动长期保留。崩溃导致证据不完整时，恢复逻辑核实执行状态，不能为了先生成回执而重跑；遵循有限临时留存规则，必要时接受诊断丢失但保留 uncertain。清理失败隔离暂存区，持久化最小资源身份与待清理状态，核验归属后恢复清理，不按同名路径盲删。测试通过与清理失败分别记录；例外本地保留须有明确目的、访问和期限策略，不能改变模型可见性。

策略变化方案已确认：读取及下一次模型请求按当前接收方和策略复核，历史可见范围不超过原发布内容与当前许可的交集。放宽策略也不自动开放旧原始日志；损坏/过期明确不可用，不重执行工具补正文。旧摘要和服务端续接历史不能绕过新权限。

泄漏后首版采用保守处置：暂停相关模型调用与依赖不确定内容的操作，本地检查受影响上下文和产物，只用确认安全的用户输入及必要可信事实重建。已受影响代码/文件不自动重新读入模型，也不自动回滚覆盖用户改动。不能确定安全时转人工，接受进度损失；不得调用另一外部模型清洗受限原文。服务端历史续接同时停止，不能仅删除本地消息后继续引用旧历史。

这一定稿采用讨论中最后收缩的方案，替代精确追踪全部派生语义并自动无损回填的首版设想。最小对象/请求身份记录用于定位和审计，但不宣称证明哪些句子未受影响。未来更细的自动影响分析属于研究扩展，不阻塞首版。

| Change | Before | After | Security consequence | Cost |
| --- | --- | --- | --- | --- |

## Recommendation

我推荐并已按用户选择固化选项 2，同时沿用选项 1 处理旧记录。我们选择相对保守的自由文本边界，用可控环境内的丰富诊断弥补信息量，而不是希望一组正则能判定任意内容安全。

如果资源只允许较小增量，可以先交付旧元数据索引和共同门禁；但不得称其已具备完整诊断能力。如果未来确需向第三方自由文本交互，应再设计明确的数据释放契约，不以模型自报标签自动升级现有权限。

## Migration And Rollout

先核实 F20/F21 的当前修复状态，再实现共同入口、完整容量门和投影契约。旧恢复历史在进入模型前必须重新按新策略投影；无法确定安全的旧正文替换成结构化不可用说明，保留协议配对和可信执行事实，不改写旧事件本身。

随后建设安全测试环境和发布存储，再开旧元数据检索、新投影读取与摘要引用，最后接入固定产物外发。新投影先做本地影子计算比对，不把影子阶段当作允许现有敏感回执继续外发的理由。特性开关可以回退检索、详细诊断或外发；模型入口和最终容量门不能因回滚而失效。

## Validation Plan

| 场景 | 必须观察到的结果 |
| --- | --- |
| stdout/stderr 含凭证、个人信息、内部数据或编码后的未知正文 | 首返、历史、恢复、摘要模型、trace 均不出现；未知输入不靠正则放行 |
| 标题、路径、测试名、错误码含敏感值 | 元数据拒绝或使用受信任固定标识 |
| 整仓库 Docker、主机 runner 或镜像存在未知输入 | 不升级为详细模型诊断 |
| 跨线程引用、伪造游标、旧授权、权限撤销、换模型接收方 | 读取拒绝，无存在性泄漏或原始正文回退 |
| 反复分页、相同页、跨 turn 重置、索引未追平 | 累计限额有效；搜索说明不完整 |
| 正文已写但发布 CAS 失败，索引损坏，正文缺失 | 孤儿不可读；可重建；不重执行有副作用调用 |
| 压缩摘要编造引用、引用已过期 | 引用不获信任或明确不可用 |
| H1 测试成功、当前 H2/配置变化 | 历史不得通过当前交付门 |
| 大工具目录、中文、长用户输入、关闭压缩、未完成调用组 | 最终容量门仍覆盖；协议组完整 |
| 上传引用被拼接、产物替换、MCP 换绑定、重定向 | 最终固定负载/目标校验拒绝 |
| 发送后超时、崩溃与恢复 | 保持 uncertain，不因重新批准而盲目重发 |
| F20 的空 seed/非空 loop、相同项数不同内容、连续压缩恢复 | 在写压缩事实前检测不一致，或经真实修复正确重放；不能仅测单轮 |
| 敏感条件真假探测、测试读宿主/凭据/网络 | 固定契约及隔离阻止任意探测 |
| 撤销/过期清理中断、旧二进制启动 | 不恢复已撤销可见性，不旁路新门禁 |

性能与能力测试必须使用相同任务、模型、配置和成本口径对比：无检索基线、元数据检索、安全投影检索；覆盖多模块修复、长失败日志、MCP 投毒、压缩后定位、同线程新 turn、kill/resume、测试配置变化。安全测试使用合成秘密，不把真实秘密交给 provider 进行试验。

## Implementation Work Packages

详细交接在[已选设计实施计划](../implementation/bounded-capture.md)。依赖为：现有恢复链核验 → 数据契约和共同门禁 → 安全诊断环境 → 投影发布 → 检索与摘要引用 → 外发适配 → 真实任务验收。各包独立验收，不以一次大改宣称全部完成。

# 首版实施契约：安全测试、回执、检索与外发

## 2. 输入与权限实例

每个测试 profile 必须由可信配置装载，模型只引用已存在的 ID，不能提交任意 JSON 作为已批准 profile。变更配置生成新版本；模型改项目中的同名文件不自动修改可信配置。

| 配置项 | 必须表达什么 | 缺失处理 |
| --- | --- | --- |
| profile_id / profile_version | 测试命令、脚本和配置的固定身份 | 拒绝执行该 profile |
| audience_policy_ref | 当前模型服务、账户/部署的可见性规则 | 不产生模型可读正文 |
| input_policy_ref | 允许的代码、依赖、合成/敏感数据与文件范围 | 不挂载未知资源 |
| candidate_admission_ref | 可自动准入的候选条件或固定候选本地批准 | 不开放敏感验证 |
| environment_ref | 镜像、运行时、平台、网络与环境变量白名单 | 不宣称满足安全诊断环境 |
| release_mode | local_only、aggregate、limited、detailed | 采用 local_only，不推断通过/失败 |
| release_fields / producer_rules | 允许字段、可信生成者、转换规则及失败值 | 未列字段不对模型展示 |
| scratch_policy_ref | 私有临时区与资源上限、清理策略 | 不启动需要临时写入的运行 |
| budget_policy_ref | 查询、运行、披露及资源的有限边界 | 禁用依赖该预算的新能力，不能用无限作为默认 |

release_mode 不单独授权：detailed 还需证明所有可达输入可发送给本次模型接收方；aggregate/limited 的每项业务事实仍需明确允许。local_only 不默认泄漏执行是否完成、耗时或输出大小。

维护者依据项目配置和无敏感输入的隔离试跑生成清单。自动补齐只在已有授权内发生，缺失资源错误不产生新权限。具体业务 profile 是部署实例：实施会话应先用合成 profile 完成验收，再绑定真实维护者配置，不为演示创建“允许所有”实例。

## 3. 可信身份与失效规则

内部 CandidateIdentity 至少绑定：仓库/工作区作用域、实际源文件集合及内容、测试集合与配置、依赖锁定结果、构建工具链/镜像/平台、允许的影响执行的环境值、输入数据的固定版本以及构建产物身份。未知字段必须显式表示，不把 unknown 当成相等。规范化编码需要固定 schema 版本、拒绝重复键/非有限数、明确排序与路径规则；不能散用普通字符串拼接。

输入哈希只用于完整性，不是访问权限。敏感低熵值的摘要不公开给模型，凭据字段/完整环境不进入事件或摘要文档。引用为不透明 ID；读取者的 principal、thread、workspace 来自可信上下文，不接受模型覆盖。

| 变化 | 缓存 | 既有批准 | 历史测试证据 |
| --- | --- | --- | --- |
| 候选代码/测试/profile 改变 | 重新匹配受影响的缓存身份 | 固定候选批准不适用 | 仍是历史事实，不证明新候选 |
| 依赖/镜像/平台/有效配置变化 | 相应构建缓存不命中 | 重新核验绑定 | 不自动视为等价环境 |
| 敏感输入版本变化或无法固定 | 不复用敏感运行产物 | 旧输入批准不适用 | 不证明新输入通过 |
| 模型接收方/数据策略改变 | 存储对象不自动删除，读取重授权 | 相关许可重新判定 | 本地事实仍在，披露可能禁止 |
| MCP 绑定/目标账户/产物版本变化 | 无关缓存可保留 | 原外发批准不适用 | 已发送事实不被撤销 |

首次测试、历史检索、交付三者分别检查身份。检索到匹配哈希不新增免测试权限；首版不引入跨 turn 自动复用测试通过结果的新路径。

## 4. 本地结果与模型回执分离

本地 ExecutionRecord 记录执行身份、实际进程状态、已知测试结论、输入证据及清理状态。模型 Receipt 是按释放契约生成的另一个对象，不能直接序列化 ExecutionRecord。测试打印的字段不能成为可信状态；运行器证明进程退出不等于证明全部规定测试通过。

拟定 Receipt 的必要语义如下，实施时可以映射到现有协议，但不得合并这些状态：

| 字段 | 允许值或含义 | 生成规则 |
| --- | --- | --- |
| schema_version | 首版协议版本 | 运行时生成 |
| receipt_ref | 已发布回执的不透明身份 | 仅在允许披露且发布成功时提供，否则为空 |
| execution_status | completed / not_completed / uncertain / withheld | 根据执行事实及释放权限；withheld 不是执行失败 |
| verdict | passed / failed / not_evaluated / unknown / withheld | completed 不自动推导 passed；未运行测试不能写 failed |
| diagnostic_status | available / restricted / unavailable | 指正文是否可读，不改变本地执行结果 |
| diagnostic | 允许的结构化字段或安全正文 | 未授权时为空；不回显原始异常 |
| applicability | 获准的候选/测试身份引用 | 不公开敏感内容哈希或真实数据路径 |
| completeness | capture_truncated、projection_reduced、read_truncated、availability | 不混淆采集丢失与本页未完；未知用 unknown |
| next_action | continue_safe_work / repair_safe_environment / reproduce_synthetic / human_required / recover_first | 可信状态和当前策略决定，不复制工具日志中的指令 |

关键组合：未开始测试而缺依赖 → not_completed + not_evaluated；已完成断言失败且可披露 → completed + failed；副作用/执行状态不确定 → uncertain + unknown + recover_first；禁止披露状态和结论 → withheld + withheld + human_required。若完成状态允许披露但结论不允许，则 completed + withheld。输出字段本身也需通过契约，无权限时采用固定提示而不是附敏感原因。

安全测试示例：已完成、失败、合成断言详情、代码身份、截断信息、真实引用。敏感例外示例：“该验证结论不向模型公开，不应据此修改补丁，后续验证由本地人工处理。”两者都不能伪称任务全部完成。

## 5. 投影发布的状态与提交点

执行状态、投影状态、索引状态和清理状态分别记录，不新增一个同时表达四者的 success。新增权威变更使用有类型 JSON 事件和精确 expected stream version；枚举和事件名在 schema 注册时固定，不允许未识别状态回退为成功。

| 起点/步骤 | 成功条件与下一状态 | 失败/崩溃后的行为 |
| --- | --- | --- |
| 执行器完成 | 先在 D7/可信执行链登记已知终态；unknown 保持 unknown | 不能用临时日志猜测成败或自动重执行 |
| 已知执行事实 → 生成投影 | 当前释放契约通过，形成固定安全 JSON | 记录投影 unavailable；执行终态不改写 |
| 写不可变正文 | 正文可读取、摘要与内容一致 | 未发布对象不可见；不能把写入错误正文发给模型 |
| 追加 published 事件 | CAS 成功后才允许产生首次正文回执 | CAS 冲突读取已提交状态；同身份不同内容拒绝；不重执行工具 |
| 更新索引 | 水位前进 | 发布不回滚；索引可重建，搜索说明不完整 |
| 撤销/过期 | 先提交 revoked/expired，立即停止读和外发 | 正文清理失败不恢复可见性 |
| 正文损坏/缺失 | 校验拒绝并记录安全不可用状态 | 不用原始日志或再次执行补正文 |

首版投影正文恰等于首次获准发布的正文，读取只分页重现它，不补出隐藏原始字节。首次呈现的权限或容量检查失败时可以不发送，但不能悄悄改已发布版本；需要不同正文时发布新身份并重新核验。

账本与投影的关联以 execution_id 和投影契约版本为基础。发布幂等只作用于发布，不授予执行幂等性。两个存储间没有共同事务时，正文先写、发布事件为可见提交点，未发布孤儿有独立清理规则。读取在响应组装完毕、离开可信边界前再次核验撤销状态；一旦已经发送，后来的撤销不能追溯撤回字节。

## 6. 临时产物清理与证据缺失

正常结束、失败与取消：先登记可持久化的事实和获准回执，再清理临时区。清理不能以“敏感原文必须长期保留”为前提。崩溃时若证据不足，保留执行 unknown；不为取得回执重跑。暂存超过有限留存策略时，可丢弃诊断并明确不可用，不伪造成功。

清理状态：active → cleanup_pending → cleaned；失败进入 quarantined，核验归属后可重试 cleanup_pending。开始清理前确认运行已停止或不再使用该资源，核对 allocation/run 身份、受控根目录内的实际对象和挂载/容器标识；同名目录不足以授权删除。不确定归属时停止删除并上报本地处理。cleaned 需要实际后置检查，不能只根据删除命令退出码。

临时文件、缓存、截图、报告和崩溃转储默认受限，不自动同步宿主、加入索引或供模型 read_file。清理失败与测试失败独立，前者不能触发补丁修改。清理状态事件只保存安全资源引用和必要身份，不包含秘密正文或完整环境。缓存回收不得删除仍被活跃运行引用的对象。

## 7. 搜索、读取和预算契约

search_tool_results 接受允许的工具/profile 标识、结果类别、时间范围和不透明游标；作用域从执行上下文取。read_tool_result 接受 result_ref 和游标。未经允许的任意正文关键词不写入外部索引或嵌入服务。返回只包括安全候选身份、允许状态、可用性、索引水位和下一游标。

每次服务端验证：调用者及 thread/workspace → 当前模型接收方与策略 → 对象状态/版本 → 游标绑定 → 有限预算 → 数据完整性 → 返回前撤销复核。不存在和不可访问对无权限调用者使用同一 result_unavailable；获准对象可分别说明过期/损坏，不能泄漏他人记录存在性。

游标绑定查询或结果、排序水位、位置、范围、版本与有效期；翻页不得跨结果版本拼接。配置变化使游标失效时要求重新搜索，不静默从其他对象继续。未知完整度不能写 complete=true。

预算至少分别计量扫描工作量、响应 UTF-8 字节、模型请求 token/保守计量、累计披露和存储。重复页/缓存命中计入披露量；新 turn 和恢复不清零任务累计预算。并发请求先以 CAS 保守预留，发送失败且是否披露不确定时不随意退还额度；允许少量额度损失，不允许借重试无限读取。

完整请求最终门在实际消息、工具快照和输出预留确定后执行，包含所有模型入口，不以压缩是否启用为前提。拒绝超限请求，不破坏 call/result 配对。没有有限配置和适用计量方法时不启用新读取能力；具体数值由基准报告提供。

## 8. 外发与人工交接

模型仅提出 export_artifact_ref 和 destination_ref 等已允许标识；服务端解析固定产物、当前内容释放规则与接收方，再构造实际负载。绑定内容、版本、目标账户/租户、工具及 MCP 身份和当前策略；D9 授权/必要批准与 D7 claim 完成后，在实际发送处核对相同对象。不能批准后替换文件或跳转到新目标。

授权既覆盖正文，也覆盖 URL/query、文件名、标题和参数。认证凭据由授权通道注入，不进入模型可见对象和事件正文。结果 timeout/unknown 不因再次批准而可重发；先按 D7 证据恢复。自由文本报告不因由模型生成就自动获得外发资格。

人工交接最少包括安全候选引用、已获准的测试证据、尚待人工验证的事项和受控本地入口。模型只收到允许的交接状态；本地用户看到的真实结论不能通过工具通用回显重新进入模型。人工确认也绑定实际候选；候选变化后旧确认不用于新交付。

## 9. 策略变化和泄漏处置

收紧策略或换接收方时，检查未来请求已有消息、摘要及服务端历史，不只检查检索。旧可见范围与当前许可取交集。已获准正文可在当前权限下重现，未知旧事件正文不能因此升级为安全投影。

发现可能泄漏：进入本地受限状态，停止相关模型发送与有依赖的操作，隔离相关上下文和产物；本地核实后仅从确认安全的用户目标和必要执行事实重建。关闭旧服务端续接，不把敏感内容交给外部模型清洗，不自动回滚用户修改。无法判断影响范围则保守放弃更大范围，不承诺无损语义恢复。

这种异常处置不要求首版构建完整语义依赖图。必须留有最小请求/对象身份以定位事件和避免重复执行；无法证明安全的内容不重新进入模型。恢复发送前重新经过入口与最终请求门，重建本身不产生新的敏感访问授权。

## 10. 验收反例与可观察结果

| 编号 | 给定情形/动作 | 必须观察到的结果 |
| --- | --- | --- |
| K01 | 模型提交自称 approved 的 profile | 不产生权限，不挂载敏感目录 |
| K02 | 依赖缺失，安装脚本索取宿主凭证 | 受控准备阶段拒绝，无敏感输入，无宿主 fallback |
| K03 | 安全测试断言失败 | 获准详细诊断，执行完成与验证失败分开 |
| K04 | 敏感测试禁止披露真实结论 | withheld/human_required，不自动改补丁或探测重测 |
| K05 | 测试未运行，环境报错 | not_completed/not_evaluated，不能标成业务失败 |
| K06 | 批准后修改候选/依赖/数据 | 旧批准不适用；固定快照不可被替换 |
| K07 | H2 通过后工作区为 H3 | 历史仍在，交付不把 H2 证据当 H3 通过 |
| K08 | 敏感测试写数据库/报告/缓存 | 私有临时区可用，但合成测试和模型读不到 |
| K09 | 写正文后发布 CAS 失败 | 不可见孤儿或合法幂等复用，无工具重执行 |
| K10 | 已发布但索引损坏 | 可重建；未命中不声称历史不存在 |
| K11 | 读取过程中权限撤销 | 返回边界前拒绝；无原始正文降级 |
| K12 | 重复页/跨 turn/并发请求绕限 | 累计额度不重置，预留冲突不放行 |
| K13 | 关闭压缩或扩大工具目录 | 最终完整容量门仍拒绝超限请求 |
| K14 | 清理命令成功但对象仍存在 | 不标 cleaned，核实隔离与重试状态 |
| K15 | 清理目标被替换为同名外部对象 | 不盲删；资源归属异常转本地处理 |
| K16 | 外发后超时，再次批准 | 保持 uncertain，不以批准清除执行不确定性 |
| K17 | 敏感缓存被提议为共享构建缓存 | 不发布；缓存键不能改变来源属性 |
| K18 | 策略撤销但旧摘要/服务端历史仍存在 | 停止相应请求，按安全重建规则处理 |
| K19 | 人工确认后候选又变化 | 确认不适用于新候选 |
| K20 | 测试宣称所有测试通过但可信证据缺失 | 不接受文本作交付事实 |

每个实施包交付设计条款 → 实际执行边界 → 测试编号的映射。跨模块集成测试必须观察最终 provider 请求和实际发送边界，不只测试中间 helper。Docker/provider 不可用的检查记录为未覆盖，不计成功。完成切片按仓库规则执行全量测试。

## 11. 实施者可决定与不可擅改的范围

可决定：内部类名、目录拆分、辅助算法和不改变契约的结构。须显式版本化：模型回执协议、事件 schema、持久化身份编码。不可擅改：权限来源、默认拒绝、失败/不可披露含义、提交点、重试条件、当前策略重检、敏感产物隔离、候选绑定。

仍需实际配置：模型接收方、数据与工具允许范围、首个真实 profile、预算配置。仍需实测：页数/累计量、目标窗口、留存、资源和成本阈值。可先用合成实例实现与测试；不要求用户再次决定架构，也不能把示例权限直接用于真实资源。只有实测迫使改变已选取舍或需要新资源权限时再商讨。

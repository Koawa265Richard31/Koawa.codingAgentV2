# R5 完整人话版：设计什么、防什么（无缺漏版）

> 本文件是 R5 全部内容的白话整理。原始文档（裁决书、验收书、代码）都
> 不如这份好读。你看这份提问就够了。
>
> 一句话背景：你的 agent 会把上下文发给外部模型服务。安全测试需要经手
> "秘密"来验证泄漏，但秘密在测试环境里转一圈（日志、缓存、文件、镜像）
> 自己就成了新的泄漏渠道。R5 就是为这个死结设计的整套设施。

---

## 第 0 章 R5 防的那个死结

安全测试有个天然矛盾：

- **要验证**："秘密会不会泄漏"这类测试，必须经手秘密才有意义（用真秘密
  当诱饵，看它会不会出现在不该出现的地方）；
- **但经手即风险**：秘密进了测试环境，就会流经日志、缓存、临时文件、
  Docker 镜像层——每一条都是新的泄漏渠道。测试本身变成了泄漏源。

R5（原名 WP-C，"安全诊断环境与适配器"）就是这个死结的解法：**用假秘密
（合成诱饵）代替真秘密 + 把测试关进隔离环境 + 出口只放"按契约允许的
诊断"**。

它同时要保住两样互相打架的东西——这是 R5 全部设计的轴心：

| 要保住什么 | 失去它的后果 |
|---|---|
| **不泄漏**：秘密（哪怕假的）不能流进模型上下文 | 测试环境变成新的秘密出口 |
| **能诊断**：测试失败时模型要拿到真实的断言和堆栈去修 bug | 安全测试变成废物——"挂了但不知道为什么"无法修 |

后面每一道设计，都是在"锁得更紧"和"还能用"之间找位置。

## 第 1 章 防线一：东西怎么进来（清单验证器）——已建成，有真代码

**设计了什么**：每次敏感测试运行前，必须提交一份**固定文件清单**——
白名单，写清楚哪些文件允许进沙箱。验证器逐条检查，任何一条不过，
整个运行直接拒绝。

**具体防什么**（每条检查对应一种攻击或事故）：

| 检查 | 防什么 |
|---|---|
| 只收相对路径、禁止 `..` | 目录逃逸——清单里写 `../../secrets.txt` 想往外跳 |
| **拒绝符号链接** | **链接逃逸**——清单条目表面上叫 `test.py`，实际是个指向宿主密钥文件的链接 |
| 必须是真实普通文件 | 目录、设备、socket 混进沙箱 |
| 单文件大小上限 + 总量上限 | 资源滥用 |
| 重复条目拒绝 | 同一文件塞两份，身份不清 |
| 拒绝 Windows 反斜杠路径 | 路径解析的绕过口子 |

**没有它会怎样**：白名单形同虚设，模型或被测代码可以借一条链接把宿主
上任何文件"合法"地带进沙箱。

## 第 2 章 防线二：东西在里面怎么活（临时世界）——已建成，有真代码

**设计了什么**：过检文件复制进一个一次性目录（名字带 uuid，每次运行
专属），内部分两区：

- `candidate/`——被测代码和测试脚本的**只读副本**（原件留在原处，沙箱
  里的是拷贝）；
- `scratch/`——**私有可写区**，测试数据库、缓存、日志、截图、崩溃文件
  全部落这里，且**全部视为敏感**。

除这两区外**一切不提供**：宿主其他目录、设备、socket、网络——想通过
"宿主 fallback"把这些能力找回来？设计原话：不存在这种通道。

**清理的品德**：运行结束（无论成功失败）由受信任的清理器删除整个目录。
**删除失败不重试**，而是把目录改名隔离（加 `.quarantined-编号`），永久
禁止复用；连改名都失败就原地不动，留给人查。

**防什么**：

| 机制 | 防什么 |
|---|---|
| 每次运行独立目录（uuid） | 新运行读到上一轮残留的敏感数据 |
| candidate 只读副本 | 被测代码反向篡改宿主原文件 |
| scratch 与宿主隔离 | 测试数据库/缓存污染宿主 |
| 清理失败 → 改名隔离、禁止复用 | 清理失败后目录被下一个运行复用，敏感残留外泄 |

**为什么删除失败不重试**：删除失败往往意味着有文件被占用或目录已部分
损坏——这种状态下重试可能删一半留一半，比不删更糟。改名隔离保证
"这个危险目录绝不会被复用"，代价只是占点磁盘（留给人工检查）。

## 第 3 章 防线三：结果怎么出去（诊断适配器 + 释放契约）

这是 R3 和 R5 汇合的地方。分两层：

### 3a. 诊断适配器（已建成，有真代码）

测试跑完，回执里**不带全文**，只带**结构化摘录**——程序从输出里提取
"哪些测试过了、失败的那个断言是什么"这类结构化信息。

**防什么**：全文泄漏。设计里的原则句：**"系统本地知道结果" ≠ "模型可以
读取结果"**——运行器什么都知道，模型只拿到释放契约允许的字段。而且输出
限制不只覆盖正文，还覆盖**文件名、路径、测试名、附件说明**——因为这些
边角信息本身就能泄密（一个测试名叫 `test_admin_login` 就暴露了系统有
管理员登录）。

### 3b. 释放契约（设计已选，实现待做）

当某个 profile 真的需要看某些字段时（比如授权的安全测试要看 argv），
不能靠删字段或贴标签，必须走一张**按接收方配置的释放规则表**。设计
已经选好（contracts.md），核心是四态释放模式：

| 模式 | 意思 |
|---|---|
| `local_only` | 结果只落在本地记录里，模型什么都别想看 |
| `aggregate` | 只给汇总（"5 过 1 挂"），不给明细 |
| `limited` | 给白名单里的字段 |
| `detailed` | 给完整诊断——但要求**证明**所有可达输入都允许发给本次模型接收方 |

**为什么这格至今没实现**：释放规则是**部署方定的策略**（哪个部署允许
什么给模型看，是维护者的决定）。写代码的人如果自己定一条"argv 永远
可以显示"，就是工程师冒充决策者。规则表的插槽没造出来之前，系统只返回
一个固定状态："没有释放规则，不可提供"——诚实站在门口，不闯进去。

**防什么**：一刀切（要么全给要么全删）；工程师发明授权；"默认全开"。

## 第 4 章 防线四：容器纪律（设计已选，实现待做）

敏感测试最终要跑在容器里（Docker）。这一章是容器的行为规范，六条裁决
（你在 09-21/22/23 拍过板的）：

**裁决一：四个区域，权限各不同**

| 区域 | 权限 | 结果处理 |
|---|---|---|
| 候选代码、测试脚本、依赖 | 固定版本、只读 | 内容一变 = 新候选身份，旧批准作废 |
| 必要敏感输入 | 授权的最小文件集合、只读、优先固定快照 | 未知或敏感输入让整个运行保持受限 |
| 专属临时目录 | 每次运行独立、可写、有资源上限 | 里面的一切（数据库、缓存、日志、截图、压缩包、崩溃文件）视为敏感 |
| 宿主其他目录、设备、socket、网络 | **不提供** | 不存在外发通道，也不能靠 fallback 找回 |

**裁决二：清单可以扩展，但只在已授权范围内**。模型可以说"缺某个依赖"，
运行时只在**已经批准的范围**内自动补；超出范围返回固定状态"需要新增
输入授权"。不能自动挂载父目录或整仓库。**目录是新文件的入口，但最终
授权对象是解析后的具体文件**——目录里新出现的文件不自动继承"可分享"
资格。

**裁决三：临时写入是常规能力，不用每次批准**（否则没法干活）；但敏感
环境里生成的文件**不自动同步回工作区、不进结果索引、不提供通用读取
接口、不作为下次测试的缓存**。

**裁决四：三种动作需要单独授权，不能打包**——新增敏感输入范围、写真实
数据、导出产物，各批各的。**审批不能扩大成"整个容器获得更高权限"**。

**裁决五：跨轮预算不可重置**。敏感验证绑定候选代码 + 测试版本 + 输入
版本 + 环境摘要；**换候选、换对话轮、崩溃恢复，都不能重置数据披露
预算**。防的手法叫"分期提取"——每次合法要一小块，拼起来是全文。

**裁决六：受限结果修不了 bug 时怎么办**——允许模型在**全新的、无敏感
输入、不复用敏感产物**的容器里尝试合成复现；仍需要真秘密才能解释的
故障，明确报告"诊断不足"，交人工。设计原话："我们不以承诺'绝不阻塞'
来降低输入、回执或外发约束。"

**防什么**：权限蠕变（一次批准被解释成永久全能）；分期提取；把"测试
环境不方便"当成放松安全的理由。

## 第 5 章 防线五：实验矩阵（设计已选，实验待跑）

**设计了什么**：把合成诱饵（假秘密）分别藏进**六种编码**，每种跑一次
完整隔离工作流，然后扫描全部出境面（回执、上下文、日志、缓存、临时区
残留）找诱饵。找到任何一个 = 失败。

| 编码 | 为什么单独测 |
|---|---|
| env 环境变量 | 子进程会继承环境变量——继承机制本身是通道 |
| 文件内容 | 最普通的通道，考基础隔离 |
| Docker 镜像层 | 删掉的文件仍留在镜像下层——"删了"不等于"没了" |
| 符号链接 | 链接在被解析的那一刻逃逸 |
| 网络 | 验证"禁网"约定是真的断了，而不只是没写配置 |
| 日志编码 | 日志框架的转义、轮转行为可能把内容带到意想不到的地方 |

**为什么六种不能合并成一次测试**：六种编码走六种**不同的泄漏机制**——
每种机制需要独立的证据。

**防什么**：只测了一种通道就声称"隔离有效"——其他五条通道全是盲区。
这也是 R5 和 R2/R3/R4 最大的不同：R2/R3/R4 的正确性靠代码和单元测试，
R5 的正确性只能靠**实验证据**——所以它没跑实验就不能声称完成。

## 第 6 章 横切纪律（贯穿所有防线的元规则）

这六条不是某个机制，是所有机制共用的价值观：

1. **工程不发明策略**——释放规则是部署方输入；实现可以执行策略，
   不能发明策略；
2. **发现 ≠ 权限**——"测试需要某个资源"的发现结果，不产生访问该资源
   的权限（依赖准备流程的核心句）；
3. **审批不能扩权**——批准一件具体的事，不等于批准一类能力；
4. **拒绝是一等状态**——不可提供要带原因独立存在，不冒充故障、不静默
   失踪（403，不是 500 也不是 404）；
5. **诚实优于完整**——没做的明说没做，验收依赖没跑的明说没跑；
   "无法在不做实验的前提下诚实声称部分完成"；
6. **不为可用性降约束**——"不以承诺绝不阻塞来降低输入、回执或外发
   约束"。

## 第 7 章 全部验收条款对照表（每条防什么）

| 验收条款 | 防的攻击/事故 | 对应防线 |
|---|---|---|
| 目录新文件与链接不能绕过清单 | 链接逃逸、后放文件 | 第 1 章 |
| 准备后输入变化被检测或用固定快照 | 检查后被调包（竞态） | 第 1 章 |
| 临时数据库/编译缓存可用但不改宿主 | 可用性与隔离的平衡被打破 | 第 2 章 |
| 敏感值藏进文件名、截图、压缩包、崩溃文件不能进模型 | 边角字段泄漏 | 第 3a 章 |
| 失败清理后的暂存区不可复用 | 残留外泄 | 第 2 章 |
| 安全重测不继承敏感缓存 | 缓存侧信道 | 第 2 章 |
| 审批不能扩大成容器通用能力 | 权限蠕变 | 第 4 章裁决四 |
| 候选代码变化不能绕过敏感验证规则 | 换个候选重试探测 | 第 4 章裁决五 |
| 跨 turn/恢复不能重置披露预算 | 分期提取 | 第 4 章裁决五 |
| 没有释放契约只返回固定不可用状态 | 工程发明授权 | 第 3b 章 |
| 非敏感测试失败有真断言堆栈 | 能诊断这一面 | 第 3a 章 |
| 宿主/Docker 不可用不静默放宽 | 静默降级 | 第 4 章 + v1 的配置期拒绝 |
| 六编码诱饵不出现在任何出境面 | 全通道泄漏 | 第 5 章 |

## 第 9 章 和其他层的关系（接线）

- **R2**：R5 里跑的敏感测试产生的结果，出境时走 R2 的四站（护照、身份、
  档案、出关章）——R5 的隔离让"进 R2 的东西"从一开始就是干净的合成物；
- **R3**：R5 的释放契约和 R3 的字段释放是**同一张配置面**——契约设计好，
  两处同时解冻；
- **R4**：隔离容器里跑的测试也要过 R4 的称重台——隔离不豁免容量；
- **模型/依赖**：实验矩阵换模型要复跑（R4 的教训同样适用）。
